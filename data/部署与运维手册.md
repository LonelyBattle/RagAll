# 部署与运维手册

本手册面向运维与实施工程师，说明星云智能客服机器人的环境要求、部署步骤、关键配置、备份升级与监控告警。

## 环境要求

私有化部署最小配置：

- CPU：8 核 16 线程以上；
- 内存：32 GB 以上（知识库超过 100 万字建议 64 GB）；
- 磁盘：200 GB SSD，其中向量索引占用的空间约为原文的 3~5 倍；
- 操作系统：CentOS 7.9 / Ubuntu 20.04+ / 麒麟 V10；
- 依赖：Docker 20.10+ 与 Docker Compose v2，或 Kubernetes 1.24+；
- 网络：需能访问大模型推理服务网关，若走内网专线需开放 443 端口。

## 部署步骤

1. **准备资源**：按环境要求准备服务器，并在防火墙放行 80/443 与控制台端口 8080；
2. **拉取镜像**：从星云私有镜像仓库拉取 `nebula-agent`、`nebula-console`、`nebula-worker` 三个镜像；
3. **初始化配置**：复制 `config.example.yaml` 为 `config.yaml`，填写数据库、对象存储与大模型服务地址与密钥；
4. **启动服务**：执行 `docker compose up -d`，等待健康检查全部通过（约 3 分钟）；
5. **初始化知识库**：登录控制台，创建知识库并导入首批文档；
6. **验证**：在控制台「调试台」提问，确认能返回带引用的答案。

## 关键配置项

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| `retrieval.top_k` | 检索返回片段数 | 5 |
| `retrieval.score_threshold` | 相似度阈值，低于此值的片段丢弃 | 0.35 |
| `chunking.chunk_size` | 切片长度（字） | 500 |
| `chunking.overlap` | 相邻片段重叠字数 | 80 |
| `rerank.enabled` | 是否开启重排 | true |
| `cache.semantic_ttl` | 语义缓存有效期（秒） | 3600 |

调大 `top_k` 能提升召回率但会增加生成耗时；`score_threshold` 调高可以抑制答非所问，但过高的阈值会导致「检索不到 → 拒答」。

## 备份与恢复

- **配置与元数据**：PostgreSQL 每日全量备份，保留 30 天；
- **向量索引**：可重建，但重建 100 万字知识库约需 2 小时，建议每周快照一次；
- **恢复流程**：先恢复数据库，再恢复对象存储中的原文，最后重建向量索引。

## 升级与回滚

小版本升级可滚动进行，先升级 worker 再升级 console，服务不中断。大版本升级前必须做一次完整备份，并在预发环境验证知识库导入与检索效果。回滚只需切回上一版本镜像并恢复数据库快照。

## 监控与告警

建议采集以下指标并配置告警：

- 检索命中率（有结果的请求占比）：低于 70% 告警，通常意味着知识库覆盖不足；
- 平均首字延迟（TTFT）：超过 2 秒告警；
- 大模型调用失败率：超过 1% 告警；
- 队列积压深度：持续大于 100 说明并发不足，需要扩容。

日志默认保留 7 天，审计日志保留 180 天，可在配置中调整。
